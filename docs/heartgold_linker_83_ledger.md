After each package, relink the **real** `heartgold` target and record *new* unresolved symbols, not just removed symbols.

## Completion rules

1. First validate the authoritative current 83-symbol snapshot using the final Apple ARM64 linker diagnostic, not just syntax checks.
2. For each package, inspect its real source bodies, emitted object symbols and ABI/layout contracts. Replace the proposed change text with the exact edited file, symbol, changed signature/line range, and test **after** source review.
3. Implement shared repairs once; do not create 83 wrapper functions or force every overlay into main.
4. Rebuild the actual `heartgold` target, re-extract undefined names and update all matching ledger rows. Track newly exposed symbols separately as new rows with provenance.
5. Re-run the 805 ARM64 object check, 129 overlay syntax check, and the full configured test suite; track runtime startup only after the full executable links.
6. Never mark a symbol **Verified** merely because its provider source exists; require successful symbol resolution, preserving original semantics and a relevant test.
