# Network production admission

`heartgold_guest32_network_admission` runs one strict batch against the configured
production provider registry and the completed original provider closure. It is
an admission attempt, not an alternative game target. Rejection is fatal to this
target and does not publish guest providers under native ABI names.

The batch relinks complete OVY_0 and OVY_38 archives with canonical original-image
install names. The existing production Mach-O binding verifier checks every
actual bind slot against emitted original providers, including native imports;
the existing image preflight still rejects automatic initializers and TLS.
Outputs live in `native-overlays/guest32-admission` under the selected build.
They remain staged and are not added to the executable merely because they link.

Original consumer images 39, 44, 45, 73, 75 and 90–93 are planned as whole images
and compiled where the existing planner can prove their DS storage. OVY_75's
demonstrated transitive GTS and title-screen owners are attempted too. Planning
retains prior code identities, actual provider signatures and main storage.
New caller declarations cannot replace an existing definition's ABI. Actual
call operands still pass through the existing missing-argument rejection.
Identical header inlines coalesce only with original source/line/body/signature
evidence. Different source-local C++ inline definitions are not silently merged.

The production closure build now roots `CodeEntryArgs_New` and `ListMenuInit`,
which the complete OVY_75 link actually demanded. Existing closure traversal
selects their original whole members and transitive dependencies. No subset
provider, LP64 alias, callback thunk or new import dispatcher is synthesized.

The guest image frontend compiles C++ through the original 32-bit frontend ABI;
C++ members contribute to the complete translation-unit count and archive checks.
A frontend census survives later code-ownership failures. Unsupported assembly
diagnostics also survive lowering. The shared data parser accepts multiplication
in integer constant expressions, needed by the original Swalot scene-node table's
`.space 16 * 11`; it does not accept arbitrary expressions or execute code.
Original assembly `FS_OVERLAY_ID(name)` constants are resolved through the
verified original SDK macro and original manifest IDs. Unknown macro calls still
fail. This removes the GTS data parser blocker while retaining rejection of its
unplaced original sections.

`admission.json` contains actual link results, missing original guest imports,
whole-member compilation results and remaining storage/ABI/state obligations.
The partial native provider link probes preserve their real flags and identify
emitted guest candidates without treating their names or DS extents as proof of
native compatibility. Potential duplicate main state is reported separately.

The generalized checkpoint reproduces historical source placements from pinned
Git blobs: full identical sections, or retained contiguous ranges with agreeing
named anchors, must match every byte and relocation target. Original membership,
image ownership, interior labels and section-tail views are checked independently.
No address is inferred from an After relationship or a merely similar substring.
The five OVY_39/90–93 guest archives and OVY_73 now compile completely. The actual
generated data loaders for the five owners are replayed against independently
constructed expected bytes in checked arenas under ASan/UBSan.

OVY_44 now compiles completely using four source-hashed original ARM call edges
across two original C members. Adjacent calls prove preservation of r0; historical
callee renames are checked against Git evidence. Missing evidence, a clobbered
word, an incorrect register lane, a wrong SSA producer or an unproved narrow
return extension still rejects. This does not authorize arbitrary missing inputs.

C++ identity normalization preserves source-file inline bodies only with closed
direct uses. Shared-header callers, assembly references, address escapes and
outside consumers prevent privatization. Original Makefile exception policy is
retained, including its per-member exceptions-on overrides. The original two
NewHandler implementations retain their distinct vtable stores. OVY_45 remains
rejected at the header-referenced Str constructor identity and original prototype
conflicts; an old coverage file is not evidence of a current complete image.
An incomplete external type may supply only its verified guest coordinate; no
layout or native object is synthesized. TLS still requires explicit thread ownership.

At present the batch rejects production admission. Native entry calls lack a
guest arena and verified pointee/callback conversion. Main native/guest state
ownership and complete image initialization/reset are unresolved. Missing ARM
call arguments require original machine evidence; the batch never invents them.
Unplaced original assembly sections and conflicting C++ inline definitions also
remain fatal. The existing native production links keep their strict failures.

The rejection regression checks real compiled artifacts and original ABI failure
sites. Passing that test establishes correct rejection and verified staged links,
not successful game admission, completed image residency, or execution of NitroMain.
